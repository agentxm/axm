# Behavioral evaluation cases

Run each prompt in a fresh agent context with the skill and the
software-architecture knowledge bundle. Do not provide the expected output or
assertions to the test agent. `evals.json` is the machine-readable authority.

The cases cover successful authoring from accepted functional, product
quality, and structural meaning; refusal to turn an unresolved design option into accepted
architecture; explicit reconciliation when desired and implemented state
disagree; rejection of an exhaustive prose mirror; scale-neutral capability,
feature, surface, and context relationships; C4 containment; strategic-map
freshness; demand-and-value modeling without a false product hierarchy; and
progressively disclosed architecture-doc organization. Focused cases also
cover one-artifact authoring for offerings, Jobs to Be Done, bounded contexts,
and C4 containers without generating sibling concepts for symmetry.
They also cover one named concept from first admission, recommendation-only
adjacent concepts, and focused authoring for every required system-context,
decision, and constraint type: lifecycle, ownership, decision policy, assurance,
accepted ADRs, and atomic binding constraints. The cases require justified
absence conclusions, keep policy separate from records, refuse unresolved
proposals as ADRs, reject a constraint-set catch-all, and avoid speculative
lower-level ownership docs.
They also cover one named Product Quality Requirement, earned ISO/IEC 25010
classification paths, external measure authority, and refusal to manufacture a
quality catalog or target.

The routing matrix distinguishes initial setup, bounded authoring, established
corpus reconciliation, and an ambiguous request using only the three same-pack
skill discovery surfaces. A fixture-backed execution case verifies that legacy
unprofiled Markdown is preserved as migration input, routes required adoption
to setup, and has no adapter-observed modification.

The suite passes when the skill produces the smallest useful architecture
artifact, preserves authority boundaries, routes exact mechanics to their
owners, requires OKF and profile conformance before authoring, and
exposes rather than resolves missing architecture decisions or unauthorized
corpus changes.
