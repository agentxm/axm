# Documentation workflow

When a question keeps coming up, how much new documentation does it need?
Suppose festival volunteers keep asking when loaned instruments are due
back. Adding the agreed return time and contact to the page they already
consult helps the next volunteer immediately. If similar questions recur
across events, a shared loans reference may earn a place in the collection.

The reader-need forms and quality principles live in
[Documentation craft](documentation-craft.md). Selected patterns supply the
appropriate document design; [organization guidance](../guides/organizing-and-naming-documentation.md)
addresses collection structure.

## How a reader’s question shapes the collection

Diátaxis describes an incremental way to develop a collection. Its four
forms help an author recognize what kind of help a reader is seeking.
A recurring lookup can justify a reference page even if the collection
has no tutorials. When several pages begin to answer related questions,
the relationship gives readers a reason to browse them together.[^diataxis-workflow]

## Bounded, useful improvements

A correction is useful once it answers the question that led someone to
the page.[^prior-documentation-workflow] A change to the loans agreement
could affect the volunteer guide, a confirmation message, and the contact
directory. Updating those together
gives readers a consistent answer whichever route they take. A typo in
a contact’s name might need only one correction.

## When the work is complete

A reference for the current festival stays useful while it reflects the
arrangements volunteers will encounter. An archived edition has a different
job. Labeling the year and preserving the policy then in force lets readers
recover what happened. A subsequent festival can have its own edition.
Diátaxis likewise distinguishes ongoing documentation from work delivered
once in final form.[^diataxis-workflow]
