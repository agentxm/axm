# Change Design

Change Design is the proportional technical reasoning that connects a bounded
change to applicable Requirements, Architecture, Implementation, and
verification. It is usually developed in conversation and either acted on
immediately or captured in a work item; a dedicated repository document is an
exception, not the default artifact.

- [Change Design](change-design.md) - How a bounded technical response realizes accepted Requirements and Architecture, including required Evaluation Protocols, without becoming another authority layer or requiring a standalone design document.
- [Developing a Change Design](developing-a-change-design.md) - Use when one bounded Change needs a proportional technical response; compare material alternatives, realize accepted Architecture and required Evaluation Protocols, and reconcile the exact Change Specification without taking over specification or delivery coordination.
