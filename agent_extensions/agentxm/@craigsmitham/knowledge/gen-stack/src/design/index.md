# Change Design

Change Design is the proportional technical reasoning that connects a bounded
change to applicable Requirements, Architecture, Implementation, and
verification. It is usually developed in conversation and either acted on
immediately or captured in a work item; a dedicated repository document is an
exception, not the default artifact.

- [Change Design](change-design.md) - How a bounded technical response connects Requirements and Architecture to Implementation without becoming another authority layer or requiring a standalone design document.
- [Developing a Change Design](developing-a-change-design.md) - Use when a change has materially ambiguous or consequential implementation choices; develop a proportional technical response and retain it in the conversation, a work item, or an explicitly governed durable document.
