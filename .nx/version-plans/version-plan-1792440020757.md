The lint rule contexts share one `ExtensionFileAccessor` and one generic `ManifestRuleContext`, built by `makePlatformFileAccessor` or `makeVftFileAccessor`, in place of a per-type accessor and context for each extension type. The skill and pack catalogs now build their `skill.json` and `pack.json` rules from the shared manifest envelope, so the envelope rules produce no findings for a non-native skill, including `skill/standalone-declaration-valid` and `skill/recommended-packs-valid`.
