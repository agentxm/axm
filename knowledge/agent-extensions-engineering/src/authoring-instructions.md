# Authoring scoped instructions

Work on the effective instruction system, including canonical sources,
imports, aliases, generated regions, and projections. A filename alone does not
establish authority or precedence.

## Resolve and author

1. Bind the repository, target scopes, supported hosts, and requested changes.
2. Establish the actual host contract: recognized sources, loading conditions,
   scope, composition, conflict resolution, and effective-context inspection.
   Do not assume narrower files always override broader ones.
3. Identify each canonical owner. Use the owning manager to inspect and
   regenerate managed output; never repair a projection by editing it directly.
4. Choose representative entry points: broad work, work within a distinct local
   scope, and adjacent work that must not receive that scope's guidance.
5. Inventory overlap, contradictions, stale commands, broken links, missing
   routes, and useful knowledge that a proposed removal would strand.
6. Retain stable consequential invariants, non-obvious working commands,
   high-value discovery routes, and stable environment facts. Put reusable
   procedures in skills or guides, explanations in knowledge, and mechanically
   decidable constraints in checks.
7. Place each instruction at the smallest truthful supported scope. Create a
   local file only for a real applicability boundary. Remove parent-child
   duplication and make task-specific commands conditional.
8. State outcomes and necessary constraints. Keep exact mechanisms and ordering
   when they protect authority, integrity, or another real requirement; leave
   routine implementation choices to the agent.
9. Update discovery routes, reconcile conflicts, and synchronize owned outputs.

## Verify the effective interface

From each representative working location, inspect the selected sources and
follow their routes. Confirm the broad guidance is available, local guidance
applies only where intended, adjacent work avoids irrelevant detail, and
precedence matches the host contract. A valid Markdown file is insufficient.

When claiming improvement, compare with prior, smaller, or absent guidance on
representative tasks. Measure outcome, adherence, unnecessary work, tokens,
latency, and safety separately. Loading and adherence alone do not establish
value. Without comparative evidence, report structural validation and leave
behavioral improvement unproven.

Record ownership and review triggers. [Review](reviewing-extensions.md) evaluates
this same effective surface without silently changing policy or content.
