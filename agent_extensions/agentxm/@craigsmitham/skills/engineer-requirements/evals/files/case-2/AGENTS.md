# Synthetic Orbit requirement policy

- Use identifiers in the form `ORB-REQ-###`; assign `ORB-REQ-117` for this case.
- Classify requirements as `capability`, `service-quality`, or
  `governance-constraint`; use `capability` for subscription access behavior.
- A requirement is normative only when linked to an accepted decision record.
- Preserve the decision identity in the native `decision record` field.
- Include the cancellation condition and paid-interval boundary, but do not
  prescribe billing, scheduling, or authorization implementation.
