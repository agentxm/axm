# Verifying extension behavior

Derive checks from the requested contract and consequences. Do not add a large
suite solely to mirror prose. Prefer existing trusted host and manager checks.

| Claim                         | Needed evidence                                                        |
| ----------------------------- | ---------------------------------------------------------------------- |
| Package is structurally valid | Applicable schema and format checks                                    |
| Archive is complete           | Effective archive paths, integrity, and required resources             |
| Host receives the extension   | Projection inspection for the selected host                            |
| Routing is useful             | Clear and paraphrased positives plus adjacent negatives                |
| Workflow works                | Representative task artifacts and observed completion/failure behavior |
| Change improves results       | Comparison with a prior, smaller, or absent-extension baseline         |
| Portable across hosts         | Evidence from each claimed host and its conditions                     |

Bind evidence to exact source or archive identity, host, model when relevant,
configuration, task, and observations. Preserve raw outputs for meaningful
behavioral claims. A summary saying a check passed is weaker than its observable
artifact. Do not infer runtime enforcement from a manifest.

For a knowledge router, verify every concept locator and exercise selecting the
right route without loading unrelated sections. Include create, revise, review,
remediation, a mixed-type request, a missing dependency, and an adjacent software
task. Same-agent walkthroughs are authoring smoke; label them accordingly.

Before executing package-controlled content, inspect identity, provenance, code,
dependencies, inputs, outputs, and side effects, and establish bounded execution
authority. Use synthetic inputs and isolated consumers where appropriate. Do not
borrow host credentials or perform real external mutations merely to test a
skill unless that exact action is authorized.

Keep outcome quality, adherence, trajectory, safety, token cost, latency, and
unnecessary work separate. Use held-out cases and repeated trials when stochastic
variation matters. Avoid tuning against the same cases used to claim success.
Report unavailable mechanisms and untested hosts as limits. Passing structural
checks or one smoke exercise does not establish broad behavioral reliability.
