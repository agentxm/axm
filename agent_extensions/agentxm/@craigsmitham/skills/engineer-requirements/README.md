# Engineer requirements

Develops, specifies, reviews, changes, and maps evidence-aware requirements
without imposing a project method, taxonomy, architecture framework, or tool.

Install the supported pack rather than this non-standalone skill:

```sh
axm packs install @craigsmitham/packs/requirements-engineering
```

The skill reads the pack's Requirements Engineering knowledge sibling and the
consuming project's instructions. It supports source inventory, candidate
development, requirement authoring and classification, specification-method
selection, individual and set review, change impact, identity and lineage, and
native-host mapping.

It does not accept or prioritize requirements, choose architecture, implement a
solution, execute tests, manage general work items, or make legal conformance
determinations without separate authority.

Examples:

- “Turn these stakeholder notes into requirement candidates.”
- “Draft a measurable availability requirement without guessing the target.”
- “Review this requirement set for conflicts and coverage gaps.”
- “Analyze the impact of changing REQ-17.”
- “Map these requirements to our tool's native fields without writing them.”
