# TOML lockfile with labeled records

## Decision

The lockfile is `axm.lock`, a TOML document at lockfile version 1. It replaces
`axm-lock.yaml` at version 12 in project and user scope. The joined view that
planning and every command read is unchanged; only the stored document, its
codec, and its writer change.

```toml
#:schema https://axm.sh/schemas/axm-lock.schema.json
# Generated by axm; do not edit by hand. See: axm help workspace-state
version = 1

[[package]]
id = "github.com/acme/code-review"
source = { git = "https://github.com/acme/code-review.git", path = ".", format = "native" }
commit = "0123456789abcdef0123456789abcdef01234567"
git-tree = "4b825dc642cb6eb9a060e54bf8d69288fbee4904"
tree = "sha256-tree-v2:…"

[[package]]
id = "registry.agentxm.ai/@community/mcps/sentry"
source = { registry = "https://registry.agentxm.ai" }
version = "2.4.1"
archive = "sha512-…"
publisher = "hbnd_…"
tree = "sha256-tree-v2:…"

[skills]
code-review = { package = "github.com/acme/code-review", name = "@acme/skills/code-review", spec = "v1.0.0" }

[[mcp]]
package = "registry.agentxm.ai/@community/mcps/sentry"
name = "@community/mcps/sentry"

[projections.rules]
contract = 1

[projections.rules.units."AGENTS.md"]
gen = "sha256:…"
output = "sha256:…"

[tool.example]
anything = "value preserved, formatting may change"
```

- **Records.** Each retained package is one `[[package]]` record with an `id`,
  a `source` inline table, its family's immutable snapshot fields, and `tree`,
  the complete-tree integrity. Keys are kebab-case and labeled by meaning:
  `archive`, `publisher`, `commit`, `git-tree`. Acquired Packs add their
  manifest version, content identity, and `dependencies`.
- **Id is the directory.** `id` is the package's retained directory under
  `agent_extensions/`. One function computes both, and reading recomputes the id
  from `source` and refuses a mismatch.
- **Bindings.** `[skills]`, `[subagents]`, `[rules]`, `[hooks]`, `[knowledge]`,
  and `[packs]` are keyed by the local name in settings. Each value is one
  binding: `package` (a record id), `name` (the declared identity as
  `@owner/<type>/<name>`, or a bare name without an owner), `spec` (the Git
  revision the source asked for, when present), and `component` (paths within a
  distribution package). Simple bindings stay inline. Component-bearing bindings
  use a standard binding table and component subtable, after the simple bindings.
  Empty tables are omitted.
- **MCP rows.** MCP selections are `[[mcp]]` rows identified by `package` and
  `name`. A component is emitted as `[mcp.component]` before the next row.
  The in-memory key is computed from the row on read and not stored.
- **Projections.** `[projections.<kind>]` tables come after every binding, each
  with its own `contract` and a `units` table of `gen` and `output` digests keyed
  by scope-relative path. Their meaning is unchanged from the
  [name-only fences decision](name-only-region-fences-and-lockfile-projection-currency.md).
- **Tool namespace.** `[tool.<name>]` tables belong to other tools. AXM carries
  them forward on every write and never reads them for installation. Their
  values are opaque to resolution. A typed TOML carrier preserves integer and
  float kinds, negative zero, signed 64-bit integers, and temporal kinds,
  fractional precision, and offsets. Keys use code-point order; formatting and
  comments may change. A failed read never becomes an empty tool namespace.
- **Canonical writer.** AXM encodes the view and emits the whole file through
  one small emitter: fixed table order, basic strings only, inline tables for
  simple bindings and sources, standard tables for complex bindings and
  projection units, multi-line arrays for dependency and artifact lists, and
  keys and rows sorted by code point, never by locale. Identical state yields
  identical bytes on every machine. There is no in-place editing.
- **Schema header.** Line 1 is a `#:schema` directive naming the published JSON
  Schema, which describes the parsed TOML data model, so TOML-aware editors can
  validate representable structural and lexical rules. CLI checks additionally
  validate cross-record relationships, domain-parser semantics, and TOML types.
  Line 2 says the file is generated.
- **Legacy file.** A legacy `axm-lock.yaml` beside the expected `axm.lock` is
  refused in either scope as an older lockfile, whether or not `axm.lock`
  exists. Its declared version (or 0) is the observed version, and the existing
  older-lockfile recovery applies. Nothing is migrated.

Decoding stays strict: unknown keys outside `tool` are errors, Pack declaration
fields appear on a record exactly when a Pack binding selects it, `spec` appears
only on Git bindings, and every record must be bound.

## Context

Version 12 stored retained packages in a `packages` map keyed by a JSON array
serialized into a YAML string, such as
`'["git","https://github.com/acme/code-review.git",".","native"]'`. Every
binding repeated that key, and the record repeated its parts again in a
`source` block, so one source appeared three times. The same package also had
three spellings that nothing kept equal: the JSON-array key, the `source`
block, and the retained directory path. Field names were the in-memory names
(`integrity`, `publisherBindingId`, `treeIntegrity`) rather than labels a
reviewer could read.

The writer edited the YAML document in place to keep diffs small, so key and
row order depended on the history of edits rather than on content. Two
machines reaching the same accepted state could commit different bytes. The
strict schema also meant every new field required a new lockfile version;
twelve versions had accumulated before public launch, the last of them to add
projection currency.

Accepted resolution is reviewed in pull requests and resolved in merge
conflicts. A record per package, compact simple bindings, and expanded component
bindings make both readable.

## Alternatives

- **Keep YAML with readable keys.** Rejected. It fixes the key spelling but
  keeps YAML's implicit typing and indentation-sensitive merges, and the
  in-place editor would still make order depend on history. A canonical writer
  for YAML would discard the one advantage in-place editing had.
- **Version-in-key locators.** Keying records by locator plus resolved version,
  as some package-manager lockfiles do, was rejected. A package's directory
  does not include its version, so the key would disagree with the directory,
  and every update would rename the record and every binding to it. Revisions
  and digests identify the snapshot separately.
- **A sibling file for projections.** Rejected. Projection rows change in the
  same closure as accepted resolution and must commit and restore with it
  through one writer. Placing them last, under their own `contract`, keeps them
  separable in review without a second authoritative file.
- **JSON.** Rejected. It has no comments for a generated-file header, puts
  punctuation on every line that merges touch, and has no array-of-tables form
  for line-oriented records.
- **MCP rows keyed by local connection name.** Rejected. The codec is pure and
  cannot consult settings, and
  [local MCP names are connection identity](mcp-local-connection-identity.md)
  owned by settings. Keying rows by alias would duplicate that authority and
  repeat a shared source once per connection.

## Prior art

- Cargo's `Cargo.lock` uses TOML, a top-level `version`, `[[package]]` records,
  a generated-file header, and deterministic order.
- pnpm's version 9 lockfile separates package resolution records from the
  places that use them.
- PEP 751's `pylock.toml` is a standardized TOML lockfile with `[[packages]]`
  records and a `[tool]` table reserved for other tools.
- Terraform's dependency lock file identifies providers by source address and
  is rewritten whole by the tool, warning that manual edits may be lost.
- Microsoft APM pairs an agent-package manifest with a generated lockfile that
  pins resolved sources.
- Copier marks its generated answers file as overwritten by the tool and never
  to be edited by hand.

## Consequences

- Every existing workspace must re-accept its resolutions. The legacy file is
  reported as an older lockfile with the recovery route: back up and remove it,
  `axm sync --preview`, then `axm sync`. External resolutions may advance
  because the old file is not read, and its projection rows are lost, so the
  first sync refuses differing whole files until `--replace-unrecorded` is
  given once.
- A reviewer reads one record per package and compact or expanded bindings, and a
  record's `id` is the path a reviewer finds on disk.
- Hand edits and comments do not survive the next write. Byte-exact
  restoration after a withdrawn introduction holds for bytes AXM wrote.
- Projection kinds change rendering through their own `contract` without a
  lockfile version. Stored data-model changes require a lockfile version;
  equivalent TOML presentation changes do not. The expanded table layout keeps
  version 1 and the existing projection contracts.
- The published schema keeps its filename and URL; it now describes the TOML
  data model.

The accepted behaviors live as executable specifications in the
[specification catalog](../../../specifications/catalog.md), including
`cli/lockfile-rejections-name-recovery-routes` and
`workspace/lockfile/records-projection-currency`. This record explains the
choice.

## Reconsideration

Reconsider if public launch requires reading or migrating older lockfiles, if
lockfile fields must be added often enough that optional additions need a
non-breaking path, if Registry version ranges or other per-binding intent must
be locked, if projection rows grow to dominate lockfile diffs, or if MCP
connection identity moves out of settings.
