# Implementation

Implementation is the current machine-consumed realization of the system.
This section governs replaceable Implementation Units and the conservation,
observability, operational memory, and rollback needed to change them safely.

- [Bounded regeneration](bounded-regeneration.md) - Use when considering regeneration of replaceable Implementation Units; make regeneration earn trust through conservation boundaries, operational memory, and rollback.
- [Compaction and conceptual mass](compaction-and-conceptual-mass.md) - How to remove obsolete structure and compress accumulated understanding without discarding load-bearing intent or evidence routes.
- [Planning change implementation](planning-change-implementation.md) - Use when one coherent Change needs a Ready implementation course; accept the exact Ready Design, sequence realization, use required Protocols and proportional review as feedback, and plan evidence and recovery without inventing meaning.
- [Implementing a change plan](implementing-a-change-plan.md) - Use when an exact persisted Ready plan and separate mutation authority exist; accept the plan, realize the exact change, preserve evidence, and return upstream when implementation exposes unresolved meaning.
- [Shipping reviewed changes](shipping-reviewed-changes.md) - Use when one exact reviewed revision is proposed for an explicitly authorized merge, deployment, publication, or other final action; verify readiness and target, execute once, read back persisted state, and return new observations without claiming more than the action established.
