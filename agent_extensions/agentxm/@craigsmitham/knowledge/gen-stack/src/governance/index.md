# Cross-cutting governance

Guidance for authoring the required root concepts that establish the documented
System and govern lifecycle, ownership, architecture decisions, and assurance
across Intent and Architecture. These are guides about the profile kernel, not
an instantiated system kernel for this Knowledge bundle.

- [Documenting systems](documenting-systems.md) - Use when establishing a Gen Stack corpus for one system or clarifying its root subject; create the required System concept that anchors the boundary and system-wide Requirements.
- [Documenting system lifecycle](documenting-system-lifecycle.md) - Use when a system needs an accepted support state, change horizon, expected evolution, and event-driven review conditions; create the required System Lifecycle concept.
- [Documenting system ownership](documenting-system-ownership.md) - Use when stable system accountability, stewardship boundaries, continuity, and escalation routes must be explicit; create the required System Ownership concept.
- [Documenting architecture decision policies](documenting-architecture-decision-policies.md) - Use when a system needs explicit governance for which architecture choices require ADRs and who decides them; create the required Architecture Decision Policy covering thresholds, content, location, supersession, and reconsideration.
- [Documenting system assurance](documenting-system-assurance.md) - Use when system-level confidence, evidence authorities, and reassessment conditions need canonical governance; create the required System Assurance concept and link review or approval Requirements when applicable.
