Knowledge inspection names the rule set every diagnostic checks. Each diagnostic carries `ruleSet` (`okf-conformance`, `agentxm-profile`, or `registry-safety`), and an OKF conformance diagnostic carries `conformanceRule`, naming which of the three OKF 0.2 conformance rules it fails (`parseable-frontmatter`, `non-empty-type`, or `reserved-file-structure`). The `./knowledge` entry exports the rule sets, the conformance rules in specification order, and the classification of every code. Checks that mixed a conformance rule with softer guidance are split: a concept without a frontmatter block reports `missing-frontmatter` instead of `missing-type`; a superseded `timestamp` field or `# Citations` section reports `superseded-timestamp` or `superseded-citations` instead of `invalid-frontmatter`; an index whose section headings are all below level one reports `missing-index-heading` instead of `invalid-index`; and a `log.md` that carries frontmatter or lists its dates oldest first reports `unexpected-log-frontmatter` or `unordered-log-dates` instead of `invalid-log`, which now reports only date headings that are not ISO 8601 dates. Reserved files are held to the OKF index and log structure: a bundle-root `index.md` whose frontmatter declares anything besides `okf_version` reports `invalid-index`, and unparseable frontmatter in an `index.md` or `log.md` reports `invalid-index` or `unexpected-log-frontmatter` rather than `invalid-frontmatter`. Index, log, and title headings are read as Markdown renders them, so a `#` line inside a code block is not a heading and a setext heading is. Each `knowledge/<code>` lint rule's description names its rule set. A concept's display title now prefers its frontmatter `title`, then its first level-one heading, then its concept ID, so titles shown and searched by `axm knowledge concepts` change for concepts that declare one, and `missing-title` is reported only when both are absent.
